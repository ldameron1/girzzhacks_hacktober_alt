## Fast iteration loop

From `/home/ld/girzzhacks_hacktober_alt`:

```bash
npm run hackathon-refresh
```

Then hard-refresh the browser at port 3001. This rebuilds `dist/` without
restarting the server. To start the demo when it is not already running:

```bash
npm run hackathon-boot
```

The boot command is idempotent and checks `/api/health` before starting another
server. Do not switch to port 3000 for the judge demo.

## Verified API behavior

Health check:

```bash
curl http://127.0.0.1:3001/api/health
```

The live mutation endpoint was directly verified with a valid telemetry and
level payload. It returned HTTP 200 with:

- a concrete accepted mutation
- rejected mutations with validation reasons
- a patched level
- `modelUsed`
- `latencyMs`

The provider may be Google Gemma, OpenRouter Gemma, or the deterministic local
heuristic depending on availability. Read the returned provider/status instead
of claiming that every request used the Google endpoint.

## Recommended judge recording

Use a 45–60 second sequence:

1. Show the Moonlit Steamboat level and telemetry sidebar.
2. Trigger one intentional failure.
3. Keep the API monitor visible while `POST /api/mutate` and the response appear.
4. Show the provider, latency, accepted/rejected mutation counts, and rationale.

Describe the system as **telemetry-driven, placement-validated adaptation**.
Do not describe the clearance overlay as a proof of solvability.

## Recent hardening

- Fresh runs now start at the actual spawn, not the midpoint checkpoint.
- Checkpoint activation uses the tile the player is standing on.
- Pit and spike-tile deaths enter the same telemetry/mutation pipeline as enemy
  collisions.
- Reset/Replay invalidates stale mutation responses from an older run.
- Floating crumbling and bounce mutations are rejected.
- The game visuals use a consistent brass, navy, fog, lantern, and Halloween
  steamboat palette.
- Cargo blocks and route tokens use original nautical iconography rather than
  generic platform-game symbols.

## Known limitations

- A mutation request is coalesced while another request is in flight; this is
  deliberate protection against request storms, not a guarantee of one API
  call per death.
- Accepted placement is validated, but the project does not perform a formal
  solvability proof.
- The remote player-decision response is advisory; the local reflex bot owns
  movement.
- External model latency can be substantial. The API monitor is the source of
  truth for provider and timing.
- This is a local/demo server, not a production-hardened public deployment.
