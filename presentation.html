The project

Gemma learns how you fail.

A replayable precision platformer staged as a Steamboat Willie-era black-and-white reel, with original public-domain Halloween motifs. Behavioral telemetry drives targeted, guarded level mutations.

Goal

Make difficulty adaptation visible, inspectable, and fun to replay.

World

Moonlit riverboat decks, ink silhouettes, ghosts, bats, pumpkins, and bone props.

Proof

The game shows the request, response, provider, latency, diagnosis, and accepted/rejected mutations.

Speed, sprinting, jumps, hesitation, deaths, and position are collected during the run.

Model boundary

The server checks coordinates, supported types, and placement conditions before applying anything.

Honest status

The monitor distinguishes Google Gemma, Gemini, OpenRouter, heuristic fallback, and failed backend requests.

Presenter runbook

Show the loop in 60 seconds.

1 · Start

Press Start, move into a hazard, and let one death complete.

2 · Point

Point to API Exchange: → POST /api/mutate, then ← RESPONSE. The console shows model, latency, archetype, diagnosis, and accepted/rejected counts.

3 · Replay

Show the new hazard, then use Reset Stage to return to the baseline. Use B for the local reflex pilot, H for heatmap, and G for the clearance estimate.

Only call it Gemma-driven when the visible response identifies a Google Gemma model. Otherwise explain the displayed fallback path.

Live demo

Production runbook: npm run build, then npm run hackathon-boot, then visit http://127.0.0.1:3001/present. After source edits, use npm run hackathon-refresh and refresh the browser; it does not restart the server. For source/HMR work, use npm run dev.
